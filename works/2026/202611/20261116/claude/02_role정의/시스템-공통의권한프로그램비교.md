# erp-h 「시스템」 권한 ↔ 「공통」 권한 비교

> 작성 2026-11-16 · 해석: 메뉴의 「시스템」 탭과 「공통」 탭에 있는 같은 이름의 권한 메뉴를 비교하고, 두 탭이 쓰는 role 층(`SYS_*` ↔ `BIZ_*`)도 함께 정리했다.
> 근거: ① Aside 로 읽은 메뉴 API(erpadmin · dev01 · 메뉴 트리와 폴더 키 포함) ② `db/common-admin/P5-menu-system-full.sql`(두 탭을 만든 SQL) ③ `P5-menu-system-full-projection.tsv`(2026-11-11 계정별 메뉴 수 실측) ④ `S6-role-codes.md` · `P3-04-roles.sql` · `P3-27` · `P3-28`
> DB 는 직접 읽지 않았다. 화면을 열어 동작을 비교하지도 않았다.
> 3절은 별도 문서였던 「공통 › 권한 ↔ 시스템 › 권한 메뉴트리 비교」(03_role설정프로그램)를 합친 것이다(2026-11-16).

## 1. 한눈에 보기

| 항목 | 공통 | 시스템 |
|---|---|---|
| 메뉴 구성 | 폴더 6개 · 화면 49개 | 폴더 12개 · 화면 172개 |
| 성격 | 업무 전체 관리 (`BIZ_*` role 이 담당) | 플랫폼·개발·보안까지 전체 (`SYS_*` · `DEVELOPER` 가 담당) |
| 관계 | **시스템의 부분집합** — 같은 폴더 구조의 일부를 「공통」에 따로 둠 | 전체 메뉴 |
| 화면 소스 | 같음 — 시스템 쪽은 같은 화면 소스를 쓰는 별칭(`sys-` 접두어 · sharedProgram) | 〃 |
| 권한(role_service) | 화면(serviceId)마다 따로 부여 | `sys-` 별칭마다 따로 부여 |
| 이 탭을 보는 계정 | erpadmin · dev01 (그 밖에 `BIZ_ADMIN` 계열) | erpadmin · dev01 (그 밖에 `SYS_ADMIN` 계열) |

핵심: **같은 화면이어도 공통 탭의 권한과 시스템 탭의 권한은 별개 부여다.** 공통의 `ca-role` 을 열 수 있어도 시스템의 `sys-ca-role` 은 따로 부여받아야 열린다.

## 3. 「권한」 메뉴 비교 (공통 › 권한 ↔ 시스템 › 권한)

범위는 「권한」 폴더(9개 화면)이다. 권한 설정과 이어지는 「메뉴·업무그룹」 폴더의 `권한/메뉴매핑`은 3-4에서 따로 다룬다.

### 3-1. 트리 (나란히)

**공통**

```text
권한/  [MENU_BC_ROLE_GRP]
├── 권한 정의/  [MENU_CA_ROLE]
│   ├── 권한 관리  `ca-role`
│   ├── 공통권한 관리  `ca-role-common`
│   └── 발령권한 관리  `ca-role-rule`
└── 권한 부여/  [MENU_BC_ROLE_OPS]
    ├── 권한/사용자매핑  `ca-user-role`
    ├── 사용자/권한매핑  `ca-user-role-by-user`
    ├── 지정권한 관리  `ca-role-assign`
    ├── 권한위임 관리  `ca-role-delegation`
    ├── 사용자(모바일)  `co_mobileAuthMapp`
```

```text

│   ├── 권한 관리  `sys-ca-role`
│   ├── 공통권한 관리  `sys-ca-role-common`
│   └── 발령권한 관리  `sys-ca-role-rule`
```

### 3-3. 비교 결과 정리 (「권한」 폴더)

| 비교 항목 | 결과 |
|---|---|
| 폴더 구조 | **같다** — 「권한」 아래 「권한 정의」(3화면)와 「권한 부여」(6화면), 같은 깊이·같은 순서 |
| 화면 구성 | **같다** — 9개 화면이 같은 이름·같은 순서로 대응 |
| 폴더 키 | 다르다 — 공통 `MENU_BC_ROLE_GRP` · `MENU_CA_ROLE` · `MENU_BC_ROLE_OPS` ↔ 시스템 `MENU_SC_ROLE` · `MENU_SC_ROLE_DEF` · `MENU_SC_ROLE_GRANT` (공통은 `BC`/`CA`, 시스템은 `SC` 접두) |
| 화면 serviceId | 다르다 — 시스템은 공통 id 앞에 `sys-` (`ca-role` ↔ `sys-ca-role`) |
| 등급 | 같다 — **erpadmin 3 · dev01 1** (이 두 계정에서 읽은 결과. 부여가 serviceId 별로 따로여서 다른 계정은 한쪽 탭만 열리거나 등급이 다를 수 있다) |
| 기능 허용 (업로드·엑셀·다운로드·인쇄) | 같다 — 9개 화면 모두 양쪽 동일 |

알아 둘 것
- **공통 「권한 정의」의 폴더 키 `MENU_CA_ROLE`** 는 이전 설계서(`S6-menu`)에서 「권한 운영」 폴더 이름이었다. 지금은 「권한 정의」로 쓰이고, 이전 안내에 적은 「공통 › 권한 운영」은 현재 메뉴에 없다. 이름과 키가 일치하지 않는 이유는 확인하지 않았다.
- **「권한」 폴더에 「권한·겸직 신청」(`ca-role-request`)은 없다.** 개인 메뉴(`개인 › 내 요청`)로 옮겨져 있다.
- 두 트리는 같은 화면 소스를 가리키는 별칭이라(`sharedProgram`) 메뉴 구조를 바꿀 때 두 쪽을 따로 고쳐야 한다. 한쪽만 바꾸면 트리가 어긋난다.

### 3-4. 「메뉴·업무그룹」 폴더 — `권한/메뉴매핑`이 있는 곳

`권한/메뉴매핑`(`ca-role-service`)은 역할에 메뉴를 부여하는 화면인데 「권한」 폴더가 아니라 「메뉴·업무그룹」 폴더에 있다. 11-11 의 `P6-fix-20261111-mssql.sql` 이 「권한」 계열에서 이 폴더(공통 `SEC_CA_ROLE_SVC` · 시스템 `MENU_SC_MENU`, 둘 다 level 3)로 옮겼다. 옛 문서(`SCREENS-COMMON.md`)의 「공통 › 권한」 위치는 지금과 다르다.

**공통**

```text
메뉴·업무그룹/  [SEC_CA_ROLE_SVC]
├── 업무그룹 관리  `ca-biz-group`
├── 메뉴트리관리  `ca-service`
├── 권한/메뉴매핑  `ca-role-service`
└── 매뉴얼  `ca-manual-viewer`
```

**시스템**

```text
메뉴·업무그룹/  [MENU_SC_MENU]
├── 업무그룹 관리  `sys-ca-biz-group`
├── 프로그램관리  `ca-program`
├── 메뉴트리관리  `sys-ca-service`
├── 권한/메뉴매핑  `sys-ca-role-service`
└── 매뉴얼  `sys-ca-manual-viewer`
```

| 화면 | 공통 serviceId | 시스템 serviceId | 등급 erpadmin | 기능 허용(UIDPE) 공통/시스템 | 서로 다른 점 |
|---|---|---|---|---|---|
| 업무그룹 관리 | `ca-biz-group` | `sys-ca-biz-group` | 3 / 3 | - / - | 키만 다름(`sys-` 별칭) |
| 프로그램관리 | — | `ca-program` | 3 | — / UIDPE | **시스템에만 있음** |
| 메뉴트리관리 | `ca-service` | `sys-ca-service` | 3 / 3 | IE / - | **기능 허용 다름** |
| 권한/메뉴매핑 | `ca-role-service` | `sys-ca-role-service` | 3 / 3 | IE / - | **기능 허용 다름** |
| 매뉴얼 | `ca-manual-viewer` | `sys-ca-manual-viewer` | 3 / 3 | - / - | 키만 다름(`sys-` 별칭) |

- 이 폴더에서는 **`메뉴트리관리`(`ca-service`)와 `권한/메뉴매핑`(`ca-role-service`) 두 화면만** 기능 허용이 다르다 — 공통은 엑셀 가져오기·내보내기(I·E) 허용, 시스템 별칭은 불허. 같은 화면 소스라도 부여 행이 따로여서 생긴 차이다.
- 시스템 폴더에만 `프로그램관리`(`ca-program`)가 있다 — 「업무그룹 관리」 다음, 「메뉴트리관리」 앞.

| csadm·cs01·cs02·cs03·site01 | 없음 | 없음 | Aside 11-16 (하자 탭만) |

- projection(11-11)과 Aside(11-16)의 화면 수 차이(공통 46→49, 시스템 167→172)는 그 사이 화면이 추가된 결과로 보인다(예: `ca-user-role-by-user` · `ca-page-source-editor`). 원인을 확인하지는 않았다.
- 업무 관리자(`BIZ_ADMIN`)만 가진 계정은 「공통」만, 시스템 관리자 계열은 둘 다 보인다.

## 6. role 층 비교: `SYS_*` ↔ `BIZ_*`

(설계서 `S6-role-codes.md` · `P3-04-roles.sql` 기준)

| 구분 | 시스템 층 | 공통(업무) 층 |
|---|---|---|
| 관리자 role | `SYS_ADMIN` — 「시스템」 전체, 터미널·PBE 복호화 전용 | `BIZ_ADMIN` — 「공통」 전체, 요청 수신(`is_biz_admin=Y`) |
| 개발 role | `DEVELOPER` — 개발도구 전체 3 + 그 밖 조회 1 | (없음) |
| 위임 담당 | (없음) | `BIZ_MNG_01`(사용자·조직) · `BIZ_MNG_02`(기준정보) |
| 전원 role(COMMON) | `SYS_COMMON` — 개인 서비스·헤더 기능·플랫폼 필수 API | `BIZ_COMMON`(내부 직원) · `PTNR_COMMON`(협력업체) |
| 발령 role(RULE) | — | `HQ_COMMON`(본사 부서) · `SITE_COMMON`(현장) |

### 6-1. 두 층 사이의 연결 (패치로 바뀐 것)

- **P3-27 (11-11)**: `SYS_ADMIN` 보유자에게 `BIZ_ADMIN` 도 부여. 초안(U-2)은 「erpadmin = SYS_ADMIN 만」이었으나 「시스템관리자도 공통을 본다」로 바뀌었다. erpadmin 이 두 탭을 모두 보는 이유다.
- **P5-menu-system-full (11-11)**: 시스템 별칭 `sys-*` 를 만들면서 `SYS_ADMIN` · `DEVELOPER` 에게 자기 부여를 복사하고, `SYS_ADMIN` 이 없으면 `BIZ_ADMIN` 부여를 사본으로 만들도록 했다.
- **P3-28 (11-11)**: `BIZ_ADMIN` 의 불필요한 「시스템」 API 첫 마디 51개를 회수(162→111). 공통 업무 관리자가 시스템 화면의 데이터 API 를 URL 로 호출해도 열리지 않게 한 것.
- 계획표(P3) 기준으로 `BIZ_ADMIN` 이 「시스템」 탭 화면 중 가진 것은 보안 2개뿐이다. 「공통」 탭의 같은 화면은 공통 serviceId 로 따로 부여받는다.

## 7. 정리

| 질문 | 답 |
|---|---|
| 같은 화면인가 | 소스는 같고, serviceId 는 다르다 (`ca-role` ↔ `sys-ca-role`) |
| 권한은 공유되는가 | 아니다. 각각 부여해야 한다 |
| 화면에서 하는 일이 다른가 | 같은 화면 소스이므로 같은 기능. 차이는 누가 열 수 있고 어떤 등급을 받는지 |
| 어느 탭에서 권한 부여 작업을 해야 하나 | 공통 업무 담당자는 「공통 › 권한」, 시스템 관리자도 「공통 › 권한」으로 같은 일을 할 수 있다. 시스템 탭은 정책·감사 화면이 더해진 전체 메뉴 |
| 등급 | erpadmin 두 탭 3 · dev01 두 탭에서 권한 화면 1(조회만) — 두 계정 기준이며 다른 계정은 달라질 수 있다 |

## 8. 확인하지 못한 것

- 두 탭의 같은 화면(`ca-role` ↔ `sys-ca-role`)이 실제로 같은 동작을 하는지 화면을 열어 비교하지 않았다. 문서(`sharedProgram`)가 같은 화면 소스라고 한 것을 따랐다.
- 시스템 탭 `sys-*` 화면의 role_service 부여 행(어느 role 이 몇 등급으로 가졌는지)은 계획표(P3)에 없고 P5-menu-system-full 로 생성되어, DB 를 읽지 않으면 role 별로 확인할 수 없다.
- 폴더(`MENU_*`)도 서비스 행이라 폴더 자체에 부여가 필요한지, 하위 화면 부여만으로 폴더가 보이는지는 확인하지 못했다.
- 별칭 `sys-*` 의 `service.params`(`mode` · `systemScope`)가 원본과 같은지 DB 로 확인하지 못했다.
- dev01 로 읽은 트리와 erpadmin 트리는 같은 구조였다(등급만 다름). 다른 계정(csadm 등)에는 두 트리가 모두 없다.
