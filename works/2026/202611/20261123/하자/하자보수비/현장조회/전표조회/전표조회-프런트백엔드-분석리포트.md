## 3. 프런트엔드 분석 (`asSlpCst.js`)

### 3.1 화면 구성
```
TitleBar(조회 버튼)
SearchBar
  ├ 현장  : CsSiteFinder (csSiteCd / csSiteNm, remember=쿠키 cs_site_cd/cs_site_nm)
  └ 조회기간*: DatePicker srchFr ~ srchTo (yyyyMMdd, 둘 다 필수)
GridPanel "전표발행 목록"  (store=slpCstStore, 단일선택, 필터 가능, 합계행)
```

### 3.2 조회조건 (viewModel.search)
| 필드 | 의미 | 비고 |
|---|---|---|
| `csSiteCd` | 현장코드 | 파인더 `params`: `MNG_DEPT=''`, `WRK_GRD_AUTH=app.page.authLevel` |
| `csSiteNm` | 현장명 | 서버로는 전송하나 **서버가 사용하지 않음** |
| `srchFr` / `srchTo` | 조회기간 시작/종료 | 기본값 = 이번 달 1일 ~ 말일 (`onLoad`, 무음 세팅) |

### 3.3 그리드 컬럼
표시 11개 (+ 순번은 `rowNumHeader` 메타, 합계 라벨은 `rowNumSummaryLabel`)

| 헤더 | field | 타입/정렬 | 폭 |
|---|---|---|---|
| 구분 | SITE_DIV | text/center | 80 |
| 현장코드 | SITE_CD | text/center | 100 |
| 현장명 | SITE_NM | text/left | 300 |
| 발행일자 | PUBC_DT | date ymd/center | 85 |
| 회계일자 | ACCTG_DT | date ymd/center | 85 |
| 발행부서명 | ACCTGUNT_NM | text/left | 150 |
| 대표적요 | REPR_RMKS | text/left | 150 |
| 전표번호 | SLP_NO | text/center | 200 |
| 거래처명 | CUST_NM | text/left | 120 |
| 계정과목명 | ACCT_NM | text/left | 150 |
| 금액 | ACCTG_AMT | number `##,##0`/right, **summary=sum** | 100 |

숨김 7개: `TRX_NO`, `AS_AMT`, `SVC_AMT`, `MAT_AMT`, `LAB_AMT`, `EXC_AMT`, `RMKS`
→ 이 중 `TRX_NO`를 제외한 6개는 원천 SP가 반환하지 않아 **항상 빈 값**(AS-IS 이식 시 선언만 유지). 현재 서버 응답에서 `TRX_NO`도 포함되어 있으므로 숨김 컬럼 중 실제 값이 있는 것은 `TRX_NO` 하나뿐.

### 3.4 동작/이벤트
| 이벤트 | 동작 |
|---|---|
| `onLoad` | 조회기간을 이번 달로 초기화. `searchOnLoad:false` → 자동조회 없음 |
| `onSearch` | `validate()` 통과 시 `getSheet1()` 호출. 조회 후 첫 행 선택은 프레임워크(CONFIG grid.select.first)가 처리 |
| `onSearchFieldChange` | ① `srchFr` 변경 시 `srchTo`를 해당 월 말일로 자동 계산 ② 그리드 데이터 비우고 selection 해제 |
| `validate` | `srchFr`/`srchTo` 중 하나라도 비면 `CS_REQUIRED_ITEM`(조회기간) 토스트 경고 |
| `getSheet1` | `app.post('/csd/getGrd_AsSlpCst', {action:'Q', csSiteCd, csSiteNm, srchFr, srchTo}, 'slpCstStore')` |

### 3.5 그리드 옵션 특이사항
- `ext-object-type="TCSC_SLPCST"` (확장 필드 객체 타입 지정)
- `summaryScope="filtered"` — 필터로 제외된 행은 합계에서 빠짐 (AS-IS FormulaRow 동작)
- `clearFilterOnSearch` — 조회 시 필터 초기화
- store `key: ['TRX_NO','SLP_NO']` — 자연키가 없어 거래번호+전표번호를 구분키로 사용(조회 전용이라 diff 위험 낮다고 주석 명시). 실데이터 214건에서 키 중복 0건 확인.

## 4. 백엔드 분석

### 4.1 요청 → 응답
```
POST /csd/getGrd_AsSlpCst         (@Auth, 로그인 필요)
Body : { action:'Q', csSiteCd, csSiteNm, srchFr:'yyyyMMdd', srchTo:'yyyyMMdd' }
Resp : { "data": [ {SLP_NO, SITE_DIV, TRX_NO, ACCTG_DT, ACCTG_AMT, CUST_NM,
                    PUBC_DT, REPR_RMKS, SITE_CD, SITE_NM, ACCTGUNT_NM, ACCT_NM}, ... ] }
```
- 컨트롤러는 `csSiteCd`, `srchFr`, `srchTo` 3개만 읽는다. (`action`, `csSiteNm` 무시)
- 컨트롤러 Javadoc의 "엔드포인트 `/api/cs/slp-cst-q/list`" 표기는 실제 매핑(`/csd/getGrd_AsSlpCst`)과 불일치 — 문서 주석 오기.

### 4.2 서비스
- `@UseDataSource(systemId="ERP", datasourceId="MAIN")` — 업무 MSSQL 라우팅
- 계정코드는 하드코딩이 아니라 `CsConfig.acctDefectAllowance()` (설정키 `acct.defect-allowance`, 기본 `6850000`)
- 원천 SP에 검증 로직이 없어 서비스에도 검증 없음

### 4.3 SQL (`erp-csc-slpCstQ.xml` → `selectSlpCstList`)
MyBatis `<include refid="hmplus.erp.common.hmpcode.mapper.HmpCodeFn.comCode"/>`(`erp-common-hmpCode.xml:185-212`)와 `#{...}` 파라미터를 모두 풀어 쓴 **MSSQL 실행용 전체 SQL**이다. 변수(`DECLARE`)를 쓰지 않고 값을 직접 넣어, DBeaver 등 문장 단위로 실행하는 도구에서도(`Ctrl+Enter`) 그대로 실행된다. 하단 `WHERE`의 리터럴 3곳(`6850000`, 기간 `20250101`~`20261130`, 현장코드 `N''`)만 필요에 맞게 바꾼다.
(변수 방식은 `DECLARE`와 `SELECT`가 다른 배치로 쪼개지면 "Must declare the scalar variable '@acctDefect'" 오류가 나서 제거함.)

```sql
SELECT A.SLP_NO           AS SLP_NO
      ,D.CD_NM            AS SITE_DIV
      ,A.TRX_NO           AS TRX_NO
      ,A.ACCTG_DT         AS ACCTG_DT
      ,A.ACCTG_AMT        AS ACCTG_AMT
      ,A.CUST_NM          AS CUST_NM
      ,B.PUBC_DT          AS PUBC_DT
      ,B.REPR_RMKS        AS REPR_RMKS
      ,C.SITE_CD          AS SITE_CD
      ,C.SITE_NM          AS SITE_NM
      ,E.ACCTGUNT_NM      AS ACCTGUNT_NM
      ,F.ACCT_NM          AS ACCT_NM
  FROM VPLUS40.TFIA_SLPDETAIL A                                  -- 전표상세(기준)
       INNER JOIN VPLUS40.TFIA_SLPMASTER B                       -- 전표마스터
               ON A.TRX_NO = B.TRX_NO
       INNER JOIN VPLUS40.TCSA_SITE_INFO C                       -- 현장정보
               ON A.INVT_DEPT_CD = C.SITE_CD
       LEFT JOIN (                                               -- 공통코드 (구분 코드명) = comCode 단편 전개
           SELECT F.code_id          AS COM_CD
                , F.code_group_id    AS HRNK_CD
                , F.code_name        AS CD_NM
                , F.code_group_name  AS GRP_NM
                , F.abbr_name        AS ABBR_NM
                , F.description      AS RMKS
                , F.attribute1       AS CHRC_VAL_1
                , F.attribute2       AS CHRC_VAL_2
                , F.attribute3       AS CHRC_VAL_3
                , F.attribute4       AS CHRC_VAL_4
                , F.attribute5       AS CHRC_VAL_5
                , F.attribute6       AS CHRC_VAL_6
                , F.attribute7       AS CHRC_VAL_7
                , F.attribute8       AS CHRC_VAL_8
                , F.attribute9       AS CHRC_VAL_9
                , F.attribute10      AS CHRC_VAL_10
                , F.num_attribute1   AS NO_VAL_1
                , F.num_attribute2   AS NO_VAL_2
                , F.num_attribute3   AS NO_VAL_3
                , F.num_attribute4   AS NO_VAL_4
                , F.num_attribute5   AS NO_VAL_5
                , F.sort_order       AS SRT_SO
                , F.use_yn           AS USE_YN
                , F.valid_from       AS VALID_FROM
                , F.valid_to         AS VALID_TO
             FROM HMP.fn_code(NULL, NULL) F
       ) D
               ON C.SITE_DIV = D.COM_CD
       INNER JOIN VPLUS40.TFIZ_ACCTGUNT E                        -- 발행부서
               ON B.PUBC_DEPT_CD = E.ACCTGUNT_CD
       INNER JOIN VPLUS40.TFIZ_ACCTCODE F                        -- 계정과목
               ON A.ACCT_CD = F.ACCT_CD
 WHERE A.ACCT_CD = N'6850000'                                    -- #{acctDefect} 하자보수충당금(설정 acct.defect-allowance)
   AND A.ACCTG_DT BETWEEN N'20250101' AND N'20261130'            -- #{srchFr} ~ #{srchTo} 회계일자(yyyyMMdd)
   AND C.SITE_CD LIKE CONCAT(N'', '%')                           -- #{csSiteCd} 현장코드 전방일치 ('' = 전체, 예: N'B6H132')
 ORDER BY A.ACCTG_DT DESC
         ,B.PUBC_DT  DESC
         ,A.TRX_NO;
```

참고
- 내부 별칭 `F`(공통코드 서브쿼리 안의 `F`)와 바깥 `F`(TFIZ_ACCTCODE)는 서브쿼리 스코프가 달라 충돌하지 않는다(원본 그대로).
- 공통코드 서브쿼리는 25개 칸을 모두 내놓지만 이 화면이 쓰는 것은 `COM_CD`, `CD_NM` 둘뿐이다. 간단히 줄이려면 `SELECT F.code_id AS COM_CD, F.code_name AS CD_NM FROM HMP.fn_code(NULL, NULL) F` 로 대체해도 결과가 같다.
- `CD_NM`은 DB 세션 `hmp.lang`(앱이 커넥션마다 사용자 언어를 설정) 기준이며, SSMS 직접 실행 시 세션 값이 없으면 기본 `ko`로 나온다.
- 공통코드 조인에 그룹(`HRNK_CD`) 조건이 없고 `COM_CD`만 비교한다. 다른 그룹에 같은 코드 ID가 있으면 행이 중복될 수 있다(현재 214건·키 중복 0건으로 문제 없음).
- 사용여부·유효기간은 거르지 않는다(과거 코드명도 표시하기 위한 설계).

| 테이블 | 별칭 | 조인 | 용도 |
|---|---|---|---|
| TFIA_SLPDETAIL | A | 기준 | 전표번호·거래번호·회계일자·금액·거래처명·계정·투입부서 |
| TFIA_SLPMASTER | B | INNER (TRX_NO) | 발행일자·대표적요·발행부서코드 |
| TCSA_SITE_INFO | C | INNER (INVT_DEPT_CD=SITE_CD) | 현장코드·현장명·현장구분 |
| 공통코드(comCode) | D | LEFT (SITE_DIV=COM_CD) | 구분 코드명(언어별, 세션 `hmp.lang`) |
| TFIZ_ACCTGUNT | E | INNER | 발행부서명 |
| TFIZ_ACCTCODE | F | INNER | 계정과목명 |

## 6. 현재 화면이 0건인 원인

화면의 현장 입력값이 **코드 `ZZV_SEED1` / 명칭 `당산 휴먼플러스 아파트 3차`** 로 되어 있다.
- 실데이터에서 "당산 휴먼플러스 아파트 3차"의 실제 현장코드는 **`B6H132`** (초기이관 전표 1건, 2024-12-31).
- `ZZV_SEED1`은 시드/테스트용 코드로 보이며 6850000 전표가 없고, 조회기간(2026-11)에도 전표가 없다.
- 쿼리는 코드 전방일치(`LIKE 'ZZV_SEED1%'`)만 사용하고 현장명은 무시하므로 → **0건**.
- `remember` 옵션으로 이전에 선택한 현장이 쿠키(`cs_site_cd`/`cs_site_nm`)에서 복원되었을 가능성이 높다.

확인 방법: 현장을 비우거나 `B6H132`/`B5H178` 등으로 바꾸고, 조회기간을 2025-01-01 ~ 2025-03-31 등으로 조회.

## 7. 관찰된 이슈·개선 후보

| # | 구분 | 내용 | 영향 |
|---|---|---|---|
| 1 | 데이터 범위 | 프런트가 파인더에 `WRK_GRD_AUTH`(권한등급)를 넘기지만, **조회 API 자체에는 권한/데이터스코프 필터가 없음**. `@Auth` 로그인 검증만 존재. 사용자가 파인더를 우회해 임의 `csSiteCd`(또는 빈값=전체)로 호출하면 전 현장 전표 조회 가능. 서비스 등록은 `data_scope_org_type='LEGAL'`로 되어 있으나 SQL에는 반영되지 않음 | 중 (권한 정책 확인 필요) |
| 2 | 현장 조건 | 현장 미지정(빈값) 시 `LIKE '%'` 로 전체 조회, 서버 측 건수 제한/페이징 없음. 현재 214건은 문제없으나 증가 시 부하 | 낮음 |
| 3 | 현장명 무시 | `csSiteNm`을 전송하지만 서버는 미사용. 코드와 명칭이 불일치해도 코드 기준으로만 조회(§6 사례) | 낮음 (혼동 유발) |
| 4 | 조회기간 검증 | 프런트는 필수만 검증. `srchFr > srchTo` 검사, 서버 측 필수/형식(yyyyMMdd) 검증 없음 | 낮음 |
| 5 | 정렬 안정성 | `ORDER BY 회계일자, 발행일자, TRX_NO` — 동일 TRX_NO 내 라인(SLP_NO) 순서 비결정 | 낮음 |
| 6 | 죽은 컬럼 | 숨김 6컬럼(AS_AMT/SVC_AMT/MAT_AMT/LAB_AMT/EXC_AMT/RMKS)은 서버가 반환하지 않아 항상 빈값. 정리 또는 AS-IS 의도 확인 필요 | 낮음 |
| 7 | 문서 불일치 | 컨트롤러 Javadoc `/api/cs/slp-cst-q/list` ≠ 실제 `/csd/getGrd_AsSlpCst`. JS 주석이 참조하는 `docs/poc/cs_gap/asSlpCst.md`, `docs/poc/cs_src/PCSC_SLPCST_Q.sql` 은 현재 저장소에 존재하지 않음 | 낮음 |
| 8 | 상태 | `docs/cs/SCREEN-STATUS.md`에 asSlpCst는 `✅ / 0 / 미확인` — 검증 이력 미기록 | 정보 |
| 9 | 스키마 하드코딩 | SQL에 `VPLUS40.` 스키마 접두사 직접 기재 | 낮음 (환경 이식 시) |
