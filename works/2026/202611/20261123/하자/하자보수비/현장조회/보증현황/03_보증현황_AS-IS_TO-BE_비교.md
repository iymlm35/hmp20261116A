# 보증현황 AS-IS / TO-BE 비교 (2026-11-23)

- 비교 대상: AS-IS 캡처 `as-is.png` · AS-IS 원본 소스 `JUNGHEUNG-ERP/.../jsp/cs/csd/sponSionCst.jsp`, `sqlmap/.../SponSionCst.xml` ↔ TO-BE `pages/cs/sponSionCst.js` (localhost:8080)
- 관련 문서: [01_보증현황_요약.md](01_보증현황_요약.md) · [02_보증현황_분석.md](02_보증현황_분석.md)

## 1. 결론

AS-IS(연월 1개 조건 + 그리드 1개)와 TO-BE(조건 5개 + 탭 2개)가 다른 이유는 TO-BE에서 **기능이 추가되고 화면이 재설계**되었기 때문이다. 탭1은 AS-IS 컨버전 원형을 유지했고, 나머지는 11월에 추가된 기능이다.

## 2. 차이와 원인

| 구분 | AS-IS | TO-BE | 이유 |
|---|---|---|---|
| 조회조건 | 연월 1개 | 연월 + 만료임박(개월) · 종결여부 · 상품구분 · 현장구분 | 만료임박·종결여부·상품구분 = 기능 #12(`ADDED-FEATURES` A15). 현장구분 = PI-CS-14(`00-작업기준서`, 커밋 `ae65882`, 11/13 배포) |
| 화면 구성 | 그리드 1개 | 탭 2개 (하자보증금 현황 / 연차별 종결 단지 현황) | 기능 #12의 「종결 단지 현황」이 새 탭으로 추가(`H-CS-REDESIGN` 12번, 구분 「보강」) |
| 그리드 제목 | 하자보증금 **관리**현황 | 하자보증금 현황 | TO-BE 라벨(`SPON_SION_CST_TITLE`) 기준 |
| 시행사 헤더 | 「시행사」 2칸(코드·명 같은 헤더) | 시행사코드 / 시행사명 | 라벨 정리(`EXEC_CO_CD` / `EXEC_CO_NM`) |
| 열 때 동작 | 렌더 후 **자동 조회**(`onRenderFirstFinish → search`) | 자동 조회 없음(조회 클릭 필요) | TO-BE `searchOnLoad:false` |
| 툴바 | 조회 버튼만 | 조회 + 매뉴얼(?) + 더보기 | 신규 프레임워크 공통 UI |
| 그리드 컬럼·합계행 | 순번~시행사 + 합계행 | **동일**(컬럼 순서·합계행) | 컨버전 원형 유지 |

- AS-IS 캡처가 0건·합계 0인 것은 AS-IS DB에 데이터가 없는 환경이거나 조회 전이어서로 보인다. 쿼리 차이 때문인지는 확인하지 못했다.
- 원천 프로시저 `PCSD_SPON_SION_CST_Q` 원문은 어디에도 없어 쿼리 결과가 AS-IS와 100% 같은지는 비교하지 못했다. 매퍼 주석상 `PIVOT` → `CASE WHEN`, `LISTAGG` → `STRING_AGG`로 이식되었다.

## 3. 왜 새 화면이 아니라 탭인가

**근거**
- `H-CS-REDESIGN.md` 8장 기능 #12: 화면 = 기존 `sponSionCst`, 구분 = 「보강」, 상태 = 「반영(A15)」. 새 화면은 「새로」로 표시한다(예: #2는 「새 화면 `baseCdReq`」).
- `sponSionCst.js` 머리주석: 탭1은 「조회전용 · 컨버전 원형」, 탭2는 「기능 #12 · 법령 L-01~03·L-12 · 시행령 §39」.

**탭으로 붙인 이유(구현 구조와 「보강」 분류에서 추정)**
- AS-IS 화면(연월 → 현장별 보증금 그리드)을 그대로 보존하려고 탭1에 유지했다.
- 데이터 단위가 다르다: 탭1은 현장 1행, 탭2는 보증서(현장+연차+순번) 1행이라 한 그리드에 합칠 수 없다.
- 같은 주제라 이 화면에서 연결된다: 만료 알림 링크가 `cs_sponSionCst`이고, 공문 발송·해지·종결도 이 화면에서 수행한다. 별도 메뉴는 메뉴·권한 등록이 추가로 필요하다.

문서에서 탭 구성의 선택 이유를 직접 설명한 부분은 찾지 못했다.

## 4. 이 구조에서 생긴 문제 — 종결여부가 탭1에 적용되지 않음

조회조건 영역을 두 탭이 공유하는데, 새 조건 3개는 탭2 전용이라 탭1에서는 아무 효과가 없다.

| 종결여부 | 탭1 (하자보증금 현황) | 탭2 (연차별 종결 단지 현황) |
|---|---|---|
| 전체 | 12건 | 22건 |
| 미종결 | 12건 | 22건 |
| 종결 | 12건 | 0건 |

- 탭1: 화면 `getSheet1()`이 `searchUseYm`·`siteDiv`만 보내고(`sponSionCst.js:114-118`), 서버 쿼리(`selectSponSionCst`)에도 종결여부 조건이 없다. 만료임박·상품구분도 같다.
- 탭2: 종결 보증서(`AS_END_YN=1`)가 로컬에 0건이라 「전체」와 「미종결」이 같은 22건이다. 쿼리 자체는 정상이다.
- 탭1에 적용하려면 「종결」의 기준을 정해야 한다: ① 현장 종결(`TCSA_SITE_INFO.FINISH_DT`, 로컬 0건) ② 보증서 종결(그 현장 보증서가 전부 `AS_END_YN=1`).

## 5. 조치 선택지 (미결정)

1. 탭2를 별도 메뉴/화면으로 분리하고 보증현황을 AS-IS 형태(연월 + 그리드 1개)로 되돌린다. 메뉴·권한 등록이 추가로 필요하다.
2. 탭 전환 시 해당 탭에 적용되는 조건만 보이거나 활성화되게 한다.
3. 탭1에도 종결여부를 적용한다(§4의 기준 결정 필요).
