## 0. 리뷰

- 조회는 정상이다(탭1 12건, 탭2 22건). 처음 열면 0건인 것은 `searchOnLoad:false` 때문이며, 조회를 눌러야 채워진다.
- **합계 이중계상**: 시드 현장 `ZZV_SEED1`과 `B6H132`의 데이터가 동일해 「잔여보증금액」 합계 4,698,908,742 중 2,349,454,220이 중복이다.
- **보증사 중복 표시**: 같은 이름이 반복된다(주택도시보증공사 ×8). `STRING_AGG`에 중복 제거가 없다.
- **해지 완료 금액이 합계에 포함**: 해지된 2년차 보증금(352,418,058)이 계속 합산된다. 쿼리에 해지·종결 필터가 없다.
- **조회조건 적용 범위가 탭마다 다름**: 연월은 탭1만, 만료임박·종결여부·상품구분은 탭2만, 현장구분은 두 탭 모두.
- **이미 만료된 미종결 12건**(최고 2022-05-19)이 있으나 알림 대상은 0건이다. 「만료임박」 조건에도 만료된 건이 포함된다.
- 상품구분이 저장된 보증서가 0건이라, 상품구분 조건을 고르면 결과가 0건이다.

## 1. 화면
- 조회조건: 연월* · 만료임박(개월) · 종결여부(기본 미종결) · 상품구분 · 현장구분
- **탭1 하자보증금 현황**: 현장별 1행, 관리연차·1~10년차 보증금·잔여보증금액·보증사·시행사 (조회 전용)
- **탭2 연차별 종결 단지 현황**: 보증서별 1행, 만료일·잔여일·통보/이의기한. 버튼 [만료 안내 공문] [해지요청 공문] [해지 완료] [종결 처리], 편집은 상품구분만
- 화면을 열면 만료 알림 건수를 조회해 1건 이상이면 알림창을 띄운다(현재 0건)

## 2. 성격 · 작성 이유
- 탭1 = AS-IS 컨버전(`PCSD_SPON_SION_CST_Q`). 탭2·알림·공문·해지·종결 = 새로 만든 기능(기능 #12, `ADDED-FEATURES` A15)
- 근거: 영 §39 담보책임 종료 절차, H-REQ-016·071·261·272·300·418
- 흐름: 만료−30일 통보 → 통보+30일 이의기한 → 만료 후 종료확인서로 종결. 만료 알림은 매일 08:00 배치

## 3. 구현
- API(POST `/csd`): `getGrd_SponSionCst` · `getGrd_WrrEnd` · `getWrrAlertCount` · `setGrd_WrrPrdt` · `setFrm_WrrCnclCmpl` · `setFrm_WrrEnd`
- 흐름: Controller → `SponSionCstQService`(탭1, 관리연차 Java 계산) / `WrrEndService`(탭2·종결) → MyBatis → MSSQL
- 테이블: `TCSA_SITE_INFO` · `TCSA_TMYER_WRR` + 신규 `TCSC_WRR_MNG`(상품구분·안내·해지·종결·알림 기록)
- 공문은 팝업 `cs_gntDocDlg`(`GntClmService`)가 발송하고 안내일·해지요청일을 기록
