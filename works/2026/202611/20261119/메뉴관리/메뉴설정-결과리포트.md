# 메뉴설정(menuHConf) 작업 결과 리포트

> 작성 2026-11-20 · 대상 저장소 `products-erp-h` · 계획서 `메뉴설정-계획서.md` 기준 · 코드·SQL은 미커밋 상태이며 DB에는 적용하지 않음

## 1. 개요

- 목적: 공통 › 시스템관리 하위에 메뉴트리관리(`ca-service`)와 같은 구성의 메뉴 편집 화면을 추가하되, 좌측 프로그램 목록과 이동 버튼은 제외함
- 방식: 화면과 백엔드를 erp-h에 별도 파일로 새로 작성하고, 코딩 규칙과 흐름은 기존 코드(코어 `service.js`, `mnuMng.js`, 기존 `/mnu` 컨트롤러)를 따름
- 명칭: 작업 중 `menuSetting`에서 `menuHConf`로 변경함. 화면 표시명은 「메뉴설정」 유지
- 현재 상태: 서버 코드는 컴파일과 단위시험 통과, 화면과 SQL은 실행 검증 전

## 2. 사전 확인 사항

- 위치 변경 사유: 11/20 erpadmin 메뉴 재조회에서 시스템 › 메뉴·업무그룹 폴더(`MENU_SC_MENU`)가 응답에서 사라짐
  - 원인은 삭제가 아니라 common-asis 작업의 메뉴 시드 `seed:common-asis-54`(11/20 06:46, 183행 수정)임. `MENU_SC_MENU`는 사용 N으로 꺼졌고, `ca-service`는 「메뉴정보」로 이름이 바뀌어 공통 › 시스템관리(`MENU_CO_COZ`)로 이동함
  - 확인 근거는 `/sys/service-manage/list` 응답의 수정자·수정 시각과 `docs/work/common-asis/02-결정표.md`임
- 등록 위치 확정: `MENU_CO_COZ` 하위 level 3, sort 55
  - 하위 순서는 도움말 30, 메뉴정보(`ca-service`) 50, 에러로그(`ca-log-error`) 60 순이며 55가 비어 있음을 11/20 조회로 확인함
- 코어 의존 버전: 11/20 빌드의 `app.jar` 안 hmp-core는 2.2.125임. 계획서 초안에 적은 2.2.120과 다르며, 화면 원본(`service.js`)은 2.2.125 판을 기준으로 복제함

  - 추가: 이름 필수, ID 필수·형식(영숫자·밑줄·하이픈)·중복(기존 및 같은 요청 안), 화면·서버 종류의 프로그램 필수, 상위 존재, 구분선 하위 금지, 숨김 메뉴 하위 금지, 깊이 5 초과 금지, level은 서버가 상위+1로 계산

  - 삭제: 하위가 남는 행은 거절하고, 하위까지 함께 삭제하면 통과
- 매퍼와 XML은 두지 않음. 조회와 쓰기를 모두 코어 빈(`ServiceService`, `ProgramService`)으로 처리하여 감사 컬럼, 메뉴 캐시 갱신, 3개 DB 호환을 코어에 맡김. 계획서의 「MyBatis 매퍼 + XML」 설계에서 달라진 부분임

## 6. 한계와 미확인 사항

- 화면 렌더링: `add delete deleteUi="button"`과 `<Tools>` 슬롯 조합은 `mnuMng.js`와 코어 화면을 합친 것으로, 실제 배치를 확인하지 못함
- 메시지 키 등록 여부: 기존 `MSG_MNU_*`, `MSG_SERVICE_*` 키가 sql-h에 실제 있는지 확인하지 못함. 없으면 거절 시 키 문자열이 그대로 표시될 가능성 있음
- API 권한 판정: 서버가 URL 첫 마디(`/mnu`)로 role_service를 찾는지 미확인. 담당현장 건에서 `/csz` 파인더가 403이던 선례가 있어 구현 직후 확인 필요
- 코어 저장 동작: `GridSaveRequest<ServiceDto>` 바인딩, `batchSave`의 level·캐시 처리, 삭제 시 `role_service`·`service_i18n` 연쇄 여부는 코어 클래스 목록으로만 확인했고 실행 검증은 없음
- 수정 행의 상위 변경은 서버가 무시함. 엑셀 가져오기로 기존 행의 상위를 바꾸려 해도 반영되지 않음
- 메뉴 깊이 상한 5와 폴더 ID 4자리 형식은 코어 동작을 참고해 정한 값이며 코어와 완전 일치하는지 대조하지 않음
- `data_scope_org_type = LEGAL`은 P32b(`common-sheet`)의 선례를 복사한 값으로, 공통 시스템관리 화면의 실제 값과 대조하지 않음
- 저장 범위는 `service`(+ 이름)뿐이며 `program`·`biz_group`은 자동 생성·수정하지 않음. 계획서 5장 11번의 결정 전 기본 가정임
- 기존 메뉴정보와 기능이 부분적으로 겹치나, 기존 프로그램을 유지한 채 erp-h에 구현된 메뉴 편집 프로그램을 특정 작업의 효율을 위해 별도 재구성하는 병존 구조임(의도된 구성). 재구성 원본은 코어 `service.js` 복제이며 `mnuMng.js`는 행 추가 패턴만 참조함(확정). common-asis 작업과는 별개이며 연관은 메뉴 위치(`MENU_CO_COZ`)에 한정됨
