# 메뉴설정 화면 추가 계획서

> 작성 2026-11-20 · 근거: `products-erp-h`(db/common-admin · app/src/main/resources/pages/co · docs/work/common-admin)와 빌드된 `app.jar` 안 hmp-core 2.2.120. 서버 클래스는 `.class`라 엔드포인트만 확인했고 DB는 직접 조회하지 않았다.

## 1. 목적
- 시스템 › 메뉴·업무그룹의 **메뉴트리관리**와 같은 위치에 **메뉴설정** 프로그램을 추가한다.
- 구성은 메뉴트리관리와 같되 **좌측 프로그램 목록(트리·이동 버튼 `>` `<`)이 없다.** 우측 메뉴 목록만 남긴다.

## 2. 결정 사항 (2026-11-20 사용자 확인)
| 항목 | 결정 |
|---|---|
| 구현 위치 | erp-h `pages/co`에 신규 JS. 메뉴트리관리 화면 파일은 hmp-core jar 안이라 작업 폴더에서 고칠 수 없다 |
| 차이점 | 메뉴트리관리에서 프로그램 목록만 뺀 화면 |
| 메뉴 노출 | 시스템 › 메뉴·업무그룹 한 곳만(공통 영역 쌍은 만들지 않음) |

## 3. 현재 구조 (조사 결과)
- **메뉴트리관리**: 프로그램 ID `service`(경로 `role/service`). 메뉴 행은 `ca-service`(공통, 부모 `SEC_CA_ROLE_SVC`)와 `sys-ca-service`(시스템, 부모 `MENU_SC_MENU`) 두 개가 한 프로그램을 공유한다.
- **같은 폴더(`MENU_SC_MENU`) 순서**: 업무그룹 관리 10 · 프로그램관리 20 · 메뉴트리관리 30 · 권한/메뉴매핑 40 · 매뉴얼 50 (`db/common-admin/P31-menu-order-20261116-mssql.sql`).
- **화면 원본**: hmp-core `pages/role/service.js`(435줄). 좌측 `programTreeStore`(40~44행)와 `TransferButtons`(377행), 우측 `serviceTreeStore`(46~59행)와 `GridPanel`(383~423행).
- **서버 API**(`ServiceController` 등): `/sys/service-manage/list · save · next-folder-id · delete`, `/sys/program/list`, `/sys/biz-group/list`. 새 Java 백엔드는 필요 없다.
- **DB**: `HMP.service`(메뉴 노드) · `HMP.program` · `HMP.service_i18n` · `HMP.role_service`.
- **선례**: `pages/co/mnuMng.js`(co_mnuMng · 메뉴정보 관리)가 프로그램 트리 없이 같은 API를 쓴다. 메뉴설정과 역할이 겹친다.
- 저장소에 '메뉴설정'·`menu-setting` 이름은 없다.

## 4. 설계
### 4-1. 화면 `app/src/main/resources/pages/co/menuSetting.js` (신규)
- **복제할 것**: 우측 메뉴 목록 전체 — `serviceTreeStore`, `GridPanel`(엑셀 가져오기·내보내기 `matchKey: serviceId`, 2~5단계 펼침, `keep-selection`, `columnToggle`), 도구 슬롯(메뉴여부·사용여부·서버 체크, 폴더 추가), 컬럼 전부.
- **재사용 메서드**: `onSearch`(service-manage/list만 호출), `onAddFolder`(next-folder-id로 `MENU_F####` 채번), `onSaveService`, `onBeforeChange`, `applySvcFilter`, 아이콘 선택.
- **제거할 것**: `programTreeStore`, 좌측 `GridPanel`, `TransferButtons`, `onMoveToService`·`onRemoveFromService`, `/sys/biz-group/list` 호출. 레이아웃은 단일 패널.
- **남길 것**: `programId` 칸의 프로그램 finder가 프로그램 지정을 대신하므로 `/sys/program/list` 선로딩(`onInit`)은 유지한다.
- **기능 변화**: 프로그램을 가운데 `>` 버튼으로 일괄 이동하던 방식이 사라지고, 메뉴 행마다 finder로 지정한다. 메뉴에 안 붙은 프로그램을 한눈에 보는 목록도 없다.

### 4-2. 등록 SQL `db/common-admin/P37-menu-setting-mssql.sql` + `P37-menu-setting-down-mssql.sql`
번호는 작성 시점의 최신 P번호 다음으로 확정한다(조사 중 P36까지 확인).

| 표 | 내용 |
|---|---|
| `HMP.program` | `co_menuSetting` · 경로 `co/menuSetting` · 업무그룹 `SYS_PLATFORM` · SCREEN · 이름 '메뉴설정' |
| `HMP.service` | `co_menuSetting` · 부모 `MENU_SC_MENU` · level 3 · sort 35(메뉴트리관리 30과 권한/메뉴매핑 40 사이) |
| `HMP.service_i18n` | ko '메뉴설정', en 'Menu Setting' |
| `HMP.role_service` | `SYS_ADMIN` 등급 3 · 범위 ALL · 엑셀 가져오기·내보내기 Y |

- 등급 뜻은 메뉴트리관리와 같다: 1 조회 · 2 등록·수정·끄기 · 3 삭제.
- 멱등(`INSERT … SELECT … WHERE NOT EXISTS`), `ins_user_id`에 표지(`P37`)를 달아 되돌림 SQL이 이 행만 지우게 한다.
- 신규 설치용 시드도 `app/src/main/resources/db/module/erp/install/common/`에 같은 내용으로 둔다(사례: `cs-76-mvin-register.sql`).
- 적용 뒤 `/cache/reload-menu`를 호출한다.

## 5. 위험·확인 항목
1. **API 권한 판정**: 서버가 URL 첫 마디(`/sys`)를 대상 서비스로 보고 `role_service`를 찾는다면 새 화면에도 별도 부여가 필요할 수 있다(담당현장 건에서 `/csz` 파인더가 403이던 사례). 구현 직후 `X-Service-Id: co_menuSetting`으로 `/sys/service-manage/list`를 호출해 확인한다.
2. **업무그룹·화면 ID**: `SYS_PLATFORM`과 접두 `co_`가 맞는지 확인 필요.
3. **엑셀 버튼**: 시스템 영역 메뉴(`sys-ca-service`)는 엑셀 부여가 N이던 선례가 있어 부여 행에서 Y를 명시한다.
4. **복제본 괴리**: hmp-core 2.2.120(jar)과 운영 판이 같은지 확인하지 못했다. 코어 화면 규약이 바뀌면 복제본이 어긋난다.
5. **기능 중복**: co_mnuMng(메뉴정보 관리)와 겹친다. 이 계획에서는 통합하지 않고 차이만 문서에 남긴다.

## 6. 검증
1. sql-h에 P37 적용 → `/cache/reload-menu` → erpadmin으로 로그인해 시스템 › 메뉴·업무그룹에 '메뉴설정'이 메뉴트리관리 아래에 보이는지 확인(Aside).
2. 화면: 메뉴 목록 로딩(975행 안팎), 좌측 프로그램 목록·이동 버튼 없음, 2~5단계 펼침·체크 필터·엑셀 내보내기 동작.
3. 쓰기: 폴더 추가 → 이름 수정 → 저장 → 재조회 → 삭제. 시험 행만 다루고 기존 메뉴 행은 건드리지 않는다.
4. 권한: `SYS_ADMIN` 외 계정(`h.cs01` 등)에서 메뉴가 안 보이고 직접 호출이 거부되는지, 등급 1에서 저장 버튼이 없는지.
5. 되돌림: `-down` 실행 후 메뉴·권한 행이 사라지는지.
