# 메뉴설정(menuHConf) 계획서 — 방향과 참조 대상 요약

> 요약 2026-11-20 · 상세 내용은 `메뉴설정-계획서_상세본.md` 보존 · 진행 결과는 `메뉴설정-결과리포트.md`

## 1. 방향

- 전제: 기존 프로그램(메뉴정보, 코어 메뉴트리관리 등)은 그대로 유지하고, erp-h에 구현된 메뉴 편집 프로그램을 특정 작업의 효율을 높이기 위해 별도로 재구성하는 화면임(기존 프로그램의 대체·통합이 아님)
- 재구성 원본(확정): 화면은 코어 메뉴트리관리(`service.js`, hmp-core jar)를 복제 원본으로 삼고, erp-h `mnuMng.js`는 행 추가 패턴만 참조함
- 관계: common-asis 작업(공통·시스템 메뉴 AS-IS 재구성)과는 별개임. 연관은 메뉴 위치(공통 › 시스템관리 폴더가 그 작업으로 생긴 구조)에 한정됨
- 목적: 메뉴트리관리와 같은 메뉴 트리 편집 화면을 프로그램 목록(좌측 트리·이동 버튼) 없이 제공
- 위치: 공통 › 시스템관리(`MENU_CO_COZ`) 하위, 메뉴정보(`ca-service`) 바로 아래(level 3, sort 55)
- 구현: 화면과 백엔드를 erp-h에 별도 파일로 신설하고, 코딩 규칙과 흐름은 기존 코드를 따름
- 진행 방식: 기존 프로그램과 비교·대조하며 다듬음
- 이름: 화면 ID `co_menuHConf`, 표시명 「메뉴설정」

## 2. 확정 사항

- 별도 화면과 새 백엔드로 구현함(코어 `/sys/service-manage/*`를 호출하지 않음)
- 서버 표 쓰기는 코어 `ServiceService`에 위임하고, 저장 앞에서 메뉴 규칙만 재검증함
- 메뉴 노출은 공통 › 시스템관리 한 곳이며 시스템 탭에는 두지 않음
- 등록 SQL은 `P38-menu-hconf-*`로 작성만 하고, 적용은 리드가 수행함

## 5. 결정 필요 사항

- 저장 범위: `service`만(현재 가정) 또는 `program`·`biz_group` 자동 생성·수정 포함
- 부여 role: `SYS_ADMIN`만(현재) 또는 `BIZ_ADMIN` 추가
- 컨트롤러 URL 접두: `/mnu` 유지(현재, 권한이 `mnu` 앵커에 걸림) 또는 `/co_menuHConf`로 변경(화면 부여로 판정, 6장 참조). 변경 시 컨트롤러 `@RequestMapping`과 화면 호출 URL 4곳이 바뀜
- 영역 필터: 현재는 전체 메뉴 편집. 코어처럼 공통 영역은 업무모듈만 표시할지 결정
## 6. 주요 위험

- 기존 메뉴정보와 기능이 부분적으로 겹치는 병존 구조임(의도된 구성). 사용자 혼선을 막기 위해 용도 구분 안내 필요
- API 권한 판정이 URL 첫 마디 기준임(PLATFORM.md §4-6). 현재 코드의 `/mnu/*MenuHConf*` 엔드포인트는 화면(`co_menuHConf`)이 아니라 서버 앵커 `mnu`(「메뉴 API」)의 `role_service`로 판정됨
  - `SYS_ADMIN`은 `mnu` 3 ALL을 가져 조회·저장·삭제가 통과하므로 403 위험은 낮음
  - 반대로 `mnu` 수준 2를 가진 다른 role(HR01 등, 11/09·11/15 시드 기준)은 메뉴설정 메뉴 부여 없이도 저장 API를 직접 호출할 수 있어 권한 우회 위험이 있음
  - 대안: 컨트롤러 접두를 화면 서비스 ID와 같게(`/co_menuHConf`) 두어 P38의 `co_menuHConf` 부여로 판정하게 함. 코어 필터·nginx의 접두 통과 여부는 미확인
  - 시드는 11/09·11/15 자료이며 현재 DB의 `mnu` 부여, 호출 화면 상속 설정(`SECURITY.caller-screen-inherit.enabled`) 현황은 미확인
- 메뉴 위치(`MENU_CO_COZ`)는 common-asis 작업이 만든 구조라 그 작업의 후속 시드로 다시 바뀔 수 있음(위치에 한정된 위험)
- 코어 화면 규약이 바뀌면 복제본과 어긋날 수 있음(복제 기준 hmp-core 2.2.125)
- `MENU_CO_COZ` 폴더에는 HR01 등 level 2 role의 부여도 있음. 새 화면은 `SYS_ADMIN`(및 결정에 따라 `BIZ_ADMIN`)에게만 부여하므로, 폴더만 보이고 화면은 안 보이는 role이 생기는지 확인 필요
